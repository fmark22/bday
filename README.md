# Royal Birthday MVP

화려한 왕궁 배경의 실시간 멀티플레이 생일 대관식 웹 앱입니다.

## 실행
Node.js 20 이상 권장.

```bash
npm install
npm run server
```
다른 터미널:
```bash
npm run dev
```
브라우저에서 http://localhost:5173 접속. 같은 방 코드로 여러 브라우저에서 접속합니다. 최초 입장자는 대관식 시작 버튼을 누를 수 있습니다.

## 구현
- 주인공 한 명 / 하객 최대 29명, Socket.IO 방 상태 공유
- 주인공 WASD/위쪽 방향키 또는 전진 버튼으로 레드카펫 이동
- 왕좌 근처에서 착석, 이후 왕관 착용
- 하객 직접 박수 버튼, 실시간 애니메이션
- 왕관 착용 시 전원 축하 배너
- 모바일 기본 버튼
- 같은 방 참가자 실시간 텍스트 채팅, 최근 50개 메시지(서버 메모리), 채팅 접기/펼치기, 대관식 완료 시스템 메시지

## 한계 및 다음 작업
- 현재 캐릭터와 왕궁은 기본 3D 메시로 제작된 프로토타입. GLB 캐릭터, 걷기/앉기/박수/왕관 애니메이션과 정교한 왕궁 에셋 교체 필요
- 현재 박수 소리, 실제 파티클 폭죽, 배경 음악, 인증/DB/영속성 없음
- 서버 재시작 시 방 초기화. 운영 환경에서는 방 코드 인증, 호스트 복구, 서버측 이동 속도 검증, 입력 rate limit, HTTPS/WSS, Socket.IO 확장 어댑터 필요
- 서버와 웹을 별도 호스팅한다면 VITE_SOCKET_URL과 CLIENT_ORIGIN 환경변수 설정
- 외부 배포 전 기능 및 보안 테스트 필요

## 채팅 정책
- 닉네임 최대 20자, 메시지 최대 200자, 서버에서 650ms 간격 제한. React 텍스트 렌더링으로 HTML 실행 방지.
- 메시지는 방별 메모리에만 저장되며 서버 재시작 또는 마지막 참가자 퇴장 시 삭제됩니다.
- 공개 배포 전 신고/차단, 부적절한 메시지 관리, 인증/입장 권한 등을 추가하는 것이 좋습니다.

## v0.5: ceremony and invitations
- Hero-only private key: create a new room as hero with a secret code. Share **guest invite link** with guests and **hero-only link** privately. Never share the hero link publicly.
- A hero must start the ceremony; guests clap using the action button. The server validates roles and event order.
- Added crown-drop animation, festive confetti, and a replay button. Browser-generated birthday tune plays after a user gesture (subject to autoplay restrictions).
- Guests are placed automatically along the carpet; chat remains room-scoped and ephemeral.
- Local start: `npm install`, `npm run server`, then `npm run dev` in another terminal. Open http://localhost:5173.
- To host, set `VITE_SOCKET_URL` for the deployed Socket.IO endpoint and `CLIENT_ORIGIN` on the server. Run over HTTPS.
- Security limitations: the first joiner creates the room; anyone knowing an unused room ID can create that room first. Use unpredictable room IDs and keep the hero code private. For a production deployment, implement server-created invitation tokens and persistent role ownership.
- QA is intentionally not performed. No claims of multi-device validation or production readiness.

## v0.6: 질문으로 시작하는 입장
- 첫 화면에 생일파티 준비 안내를 약 1.8초 동안 표시한 뒤 주인공 확인 질문을 보여줍니다. 실제 에셋 로딩 진행률을 의미하지 않습니다.
- “혹시, 오늘의 주인공이신가요?”에 “네, 맞아요”를 누르면 주인공, “아니요, 축하하러 왔어요”를 누르면 하객으로 설정됩니다. 닉네임 입력 후 입장합니다.
- 방은 URL의 room 값을 사용하며, 없으면 birthday입니다. 별도 방 만들기나 주인공 코드 입력은 없습니다. 하객도 먼저 입장할 수 있습니다.
- 주인공 전용 코드와 전용 링크 방식은 폐기했습니다. 위 v0.5의 해당 설명보다 이 절을 우선합니다. 역할은 본인의 응답으로 정하며, 이미 주인공이 있는 방에서는 다른 주인공의 입장을 거절합니다.
- 서버 구문 검사, 프로덕션 빌드, 서버 입장 핸들러의 하객 선입장·코드 없는 주인공 입장·중복 주인공 거절 검증을 통과했습니다. 로컬 소켓 연결 테스트는 실행 환경의 EACCES 제한으로 완료하지 못했습니다. 브라우저 화면 및 멀티기기 검증은 별도 진행이 필요합니다.

## v0.8: 선물을 가져오는 생일파티
- 참고한 공간형 웹사이트의 화면 원칙을 적용: 전체 화면 3D 공간, 자동 이름, 작은 조작 도크, 접힌 채팅, 공간 위의 반투명 입장 화면. 외부 사이트의 코드나 에셋은 사용하지 않았습니다.
- 준비 안내 후 선물 네 가지(꽃다발·리본·별빛 망토·파티 안경) 중 하나를 선택해 입장합니다. 이름 입력과 회원가입은 필요 없습니다. 자동 이름은 다시 뽑거나 입장 후 변경할 수 있습니다.
- 주인공은 선물 없이 바로 입장할 수 있고, 주인공이 없는 방에서는 입장한 하객이 주인공으로 전환할 수도 있습니다.
- 하객은 주인공이 입장한 후 선물을 1회 전달할 수 있습니다. 꽃다발은 손, 리본은 목, 망토는 등, 안경은 얼굴에 착용되어 함께 표시됩니다. 같은 종류 선물은 중복 기록되지만 모델은 1개만 표시합니다.
- 받은 선물은 즉시 착용되며 주인공의 받은 선물 패널에서 착용/해제할 수 있습니다. 서버가 역할·아이템·전달 여부를 검사하고 같은 방의 모든 참가자에게 착용 상태를 전송합니다.
- 다시 시작은 선물과 착용 상태를 유지합니다. 모든 참가자 퇴장 또는 서버 재시작 시 방과 선물은 사라집니다. 재접속 시 자동 역할 복구는 아직 지원하지 않습니다.
- 친근한 둥근 캐릭터, 화분과 촛불, 차분한 카펫 색상을 적용했습니다.
- 검증: npm run build, npm test 통과. 테스트는 서버 이벤트 핸들러를 격리하여 선물 선택 검증, 주인공 대기, 전달·중복 방지, 착용 권한, 미수신 아이템 차단, 방 분리, 주인공 전환, 이름 변경, 재시작 유지, 늦은 입장 상태 공유를 검사합니다.
- 내장 브라우저에서 localhost:5178 연결이 시간 초과되어 실제 WebGL 화면·모바일 화면·다중 브라우저 검증은 완료하지 못했습니다.
- 서버 이벤트가 추가되었으므로 기존 npm run server 프로세스를 종료한 뒤 재실행해야 합니다.

## v0.9: 네 종류의 하객과 랜덤 배정
- design/character/guest-lineup-v1.png: 왕실 집사, 궁정 학자, 왕궁 근위병, 축하의 음유시인 고급 3D 스타일 디자인 시안. 이미지 생성 도구로 왕 시안의 소재·조명을 참고해 제작했습니다.
- 서버는 방마다 네 캐릭터를 섞어 입장한 하객에게 하나씩 배정합니다. 네 종류가 모두 배정되면 다시 섞고, 묶음 경계에서 같은 캐릭터가 연속되지 않게 합니다. 주인공 입장과 실패한 입장은 하객 배정 순서를 소비하지 않습니다.
- 캐릭터 ID는 서버가 결정하고 방 상태에 포함하여 공유합니다. 채팅·선물 전달·재시작으로 캐릭터가 바뀌지 않습니다. 연결 종료 후 재입장은 새 배정입니다.
- 하객이 주인공으로 전환하면 king ID로 바꿉니다. 이름 옆에서 배정된 역할 이름을 확인할 수 있습니다.
- 현재 실시간 3D 표현은 코드로 구현한 간소화 모델입니다. 집사의 외투·콧수염·가방, 학자의 머리 묶음·안경·로브, 근위병의 갑옷·어깨 장식, 음유시인의 베레모·곱슬머리·악기로 구분합니다. 생성한 고해상도 시안과 같은 수준의 리깅된 GLB 모델은 아직 없습니다.
- 서버 테스트에 무작위 묶음별 중복 방지, 묶음 경계 연속 중복 방지, 입장 배정, 상태 공유, 임의 ID 주입 방지, 주인공 전환 검증을 추가했습니다.

## v0.10: 실제 GLB 모델·왕궁·선물 스타일 통합
- public/models/: 왕, 집사, 학자, 근위병, 음유시인과 꽃다발·리본·망토·안경의 GLB 9개를 제작했습니다. 총 약 4.81 MB이며 각 파일은 1 MB 미만입니다. 원본 제작 스크립트는 tools/build-models.mjs, 재생성 명령은 npm run build:models입니다.
- 캐릭터는 시안의 얼굴 연령감, 수염, 체형, 예복 색상, 직업별 소품을 참고하여 직접 구성한 파라메트릭 메시입니다. 고해상도 생성 이미지에서 추출한 3D 모델 또는 시안의 자수·머리카락·모피를 그대로 재현한 디지털 조각은 아닙니다.
- 머리·팔·다리·무릎·왕관을 계층형 관절로 분리하여 걷기, 박수, 착석, 왕관 하강을 연결했습니다. 스키닝된 인체 리그가 아니므로 관절 변형은 단순합니다.
- 얼굴·머리카락 곡선·눈·코·손가락·버클·장화·실루엣을 추가하고, 옷감 sheen과 미세 bump, 금속 물성 및 로컬 환경 반사를 적용했습니다. 외부 HDRI 서버를 사용하지 않습니다.
- 선물은 GLB 액세서리로 착용됩니다. 선택 카드용 이미지(public/images/royal-gifts-v1.png)는 이미지 생성 도구로 별도 제작한 고품질 카탈로그 그림이며, 실시간 GLB의 실제 렌더 캡처가 아닙니다.
- 아치 천장 골조, 버건디 커튼, 금속 테두리, 벨벳 쿠션 장식 왕좌와 벽면 문장, 광택 석재 바닥을 추가했습니다.
- ?studio 주소에서 왕·손님 캐릭터를 회전·확대하고 선물 및 박수 상태를 확인할 수 있습니다. 예: http://localhost:5173/?studio
- 로딩 표시 및 모델 로드 실패 화면을 추가했습니다. 실제 모델 파싱·유한 정점·머티리얼·관절·높이·파일 예산 검사를 npm test에 포함했습니다.
- 빌드 및 서버/모델 검증은 통과했습니다. 내장 브라우저의 로컬 네트워크 미리보기가 시간 초과되어 최종 실제 WebGL 화면과 모바일 성능은 검증하지 못했습니다.

## 캐릭터 이름 정책 변경
- 입장 시 배정된 캐릭터의 이름(왕실 집사·궁정 학자·근위병·음유시인)을 서버가 이름표·채팅·선물 발신자 이름으로 설정합니다. 별명 뽑기와 이름 편집은 제거했습니다. 주인공 이름은 오늘의 왕입니다.

- 서버 이름 배정 및 주인공 전환 검증, 프로덕션 빌드 통과.

- 기존 소리 버튼은 음소거 상태만 바꾸고 왕관 착용 전에는 아무 오디오 소스도 재생하지 않았습니다. 박수 소리도 UI 개편 과정에서 연결이 빠져 있었습니다.
- client/audio.js에 Web Audio 음원을 분리했습니다. 입장/소리 켜기 사용자 동작 후 잔잔한 화음 배경음을 즉시 시작하고, 박수 이벤트에서 짧은 노이즈 박수 효과음을 재생합니다. 외부 음원 파일은 사용하지 않습니다.
- 생일 멜로디는 왕관 착용 시 재생합니다. 음소거 중에는 재생 완료로 처리하지 않으므로, 축하 단계에서 소리를 켜면 멜로디가 재생됩니다. 다시 시작 시 예약된 멜로디를 실제로 정지하며 배경음은 유지합니다.
- AudioContext resume 성공을 확인하고 실패하면 꺼짐으로 표시하며 사이트 소리 권한 안내를 보여줍니다. 연결 해제 및 언마운트에서 루프와 소스를 정리합니다.
- 오디오 스케줄링/음소거/재시작/정리/브라우저 차단 모의 검증과 빌드 통과. 실제 스피커 출력은 이 환경에서 확인하지 못했습니다.
